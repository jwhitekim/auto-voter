# 승인 게이트 절차

기준은 중요도가 아니라 **되돌릴 수 있는가**다. 아래 액션은 한 번 실행되면 취소가 없거나 비싸다.

## 승인이 필요한 액션 목록

- `alembic upgrade` (마이그레이션 실행)
- 배포 관련 명령
- `git push --force`
- 외부 API에 쓰기 요청을 보내는 것 (읽기는 해당 안 됨)
- 테스트 파일 삭제 또는 대량 수정
- `.env`, `.env.prod`, `secrets/` 읽기/쓰기

## 절차

1. 위 액션 중 하나를 실행해야 하는 상황임을 인지하면, **먼저 멈춘다.** 코드 작성/준비는 계속해도 되지만
   실제 실행 명령은 아직 실행하지 않는다.
2. 사람에게 아래를 보여준다.
   - 실행하려는 정확한 명령
   - 왜 필요한지
   - 되돌릴 수 없다면 무엇이 되돌릴 수 없는지
3. 사람이 명확하게 승인("실행해", "진행해" 등)할 때까지 기다린다.
4. 승인받으면 실행하고, 결과를 그대로 보고한다.

## 이 스킬이 막으려는 것

- CLAUDE.md에 목록이 있다는 걸 깜빡하고 그냥 실행해버리는 것
- "이번엔 괜찮을 것 같다"는 판단으로 승인을 생략하는 것
- 승인을 받았어도 실제로 실행한 명령이 승인받은 것과 다른 경우

## 한계 (알고 있을 것)

이 스킬은 프로세스일 뿐, 강제하는 코드가 아니다. 실행을 물리적으로 막는 건
`.claude/settings.json`의 PreToolUse Hook만 할 수 있다. 위 액션 중 하나를 처음 실행해야 하는
상황이 오면, 이 스킬로 절차를 따르는 것과 별개로 PreToolUse Hook 추가를 사람에게 상기시킨다.
