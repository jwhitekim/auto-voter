# 완료 판정 절차

"완료"는 결정적 검증기가 판정한다. LLM(나 자신 포함)이 "잘 된 것 같다"고 판단하는 건 완료가 아니다.

## 절차

1. 아래를 순서대로 실행한다.
   ```bash
   pytest -q
   mypy app/
   ruff check
   ```
2. **하나라도 실패하면 완료 보고를 하지 않는다.** 실패 원인을 분석해서 구현을 고친다.
3. **테스트 자체를 고치고 싶은 유혹이 들면, 고치지 말고 멈춘다.** 테스트가 틀렸다고 판단되면
   왜 틀렸다고 생각하는지 사람에게 설명하고 먼저 물어본다. 임의로 테스트를 바꿔서 통과시키지 않는다.
4. 셋 다 통과하면, **명령 실행 결과 전체(요약 말고 실제 출력)**를 완료 보고에 그대로 포함한다.
   "테스트 통과했습니다"라고 말로만 쓰지 않는다.

## 완료 보고 형식

```
✅ 완료: {무엇을 했는지 한 줄}

pytest 결과:
{실제 pytest 출력}

mypy 결과:
{실제 mypy 출력}

ruff 결과:
{실제 ruff 출력}
```

## 이 스킬이 막으려는 것

- "대부분 통과했다"를 완료로 보고하는 것
- 증거 없이 "잘 됐다"고 말로만 보고하는 것
- 실패한 테스트를 구현이 아니라 테스트 쪽을 고쳐서 우회하는 것
