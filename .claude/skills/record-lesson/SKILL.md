# 교훈/규칙 기록 절차

CLAUDE.md는 스스로 판단해서 고치지 않는다. 사람이 명시적으로 요청했을 때만 이 절차를 따른다.
(자동으로 배우고 기록하고 싶다면 Claude Code의 오토 메모리(`/memory`)가 이미 그 역할을 한다.
이 스킬은 그것과 별개로, git에 커밋되어 팀/미래의 나와 공유되는 명시적 규칙을 위한 것이다.)

## 절차

1. 방금 있었던 일을 한 줄로 요약해서 사람에게 확인받는다. **정확히 무엇을 규칙화할지**부터 맞춘다 —
   너무 좁게(이번 케이스만) 또는 너무 넓게(일반화 과도) 요약하지 않았는지 확인.
2. 어디에 넣을지 판단한다.

   | 성격 | 넣을 곳 |
   |---|---|
   | 매번 지켜야 하는 규칙 (짧게 한 줄로 표현 가능) | `.claude/CLAUDE.md` 관련 섹션 |
   | 배경 설명/이유가 필요함 | `docs/` 아래 관련 파일 (없으면 새로 만들지 말고 먼저 물어본다) |
   | "해봤는데 안 됐다"류의 시행착오 | `docs/learnings.md` (없으면 만들지 물어본다) |

3. `.claude/CLAUDE.md`에 추가하는 경우, 추가 후 줄 수를 확인한다. 200줄(공식 권장 상한)에
   가까워지면 `/trim-claude-md` 스킬을 고려하라고 사람에게 알린다.
4. **실제로 파일을 고치기 전에, 추가할 정확한 문구를 사람에게 보여주고 최종 확인을 받는다.**
   확인 없이 바로 쓰지 않는다.
5. 확인받으면 수정하고, `commit-and-push` 스킬 절차로 커밋한다.

## 이 스킬이 막으려는 것

- Claude가 스스로 "이건 규칙으로 만들어야겠다"고 판단해서 CLAUDE.md를 조용히 고치는 것
- 한 번의 특수 케이스를 과도하게 일반화한 규칙이 섞여 들어가는 것
- 확인 없이 문구가 확정되는 것
